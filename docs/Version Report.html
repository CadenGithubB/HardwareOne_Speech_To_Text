Inside the model run, by layer type (a 5-second phrase)

Numbers in brackets are how many layers of that type the model has. Depthwise layers are 9% of the model's arithmetic but took about a third of its time: each step read more data than the chip's 64 KB fast cache holds. Working in 64-channel blocks and splitting the channels across both cores fixed that, with bit-identical output. 1.5's prepared layer setups took a further 30 ms off, mostly in the smaller layers, where setup is a larger share; the 512-wide pointwise layers are now 60% of the run. *1.1's split comes from an older per-layer profile of the same model.

What each change did (compared one at a time)

The chip has no neural-net accelerator; its SIMD units were mostly waiting on memory. That is why the cache line was the biggest early win, and why using both cores only paid off once each core worked on its own channels. 4. Memory and accuracy by version

Lowest free PSRAM during a session (standard playlist)

Lowest free PSRAM on long unbroken speech

Out of 32 MB. 1.1 rebuilt the model for every phrase, so it held less between phrases. From 1.2 the model and its working area stay for the session (about 2.6 MB more). 1.7 halves the five session audio buffers and the feature caches: 2.7 MB more free after warm-up, and 3.8 MB more at the lowest point on long speech, where phrases used to reach 20 s. 1.8's smaller LM gives back 0.9 MB. 2.0's speaker model takes 3.4 MB: with the 1.6 MB LM about 3 MB stays free at the lowest point.

Lowest free internal RAM during a session

Internal RAM is the scarce kind (about 260-280 KB free at boot). 1.1 dipped to about 44 KB while it rebuilt the model for each phrase; from 1.2 the model is built once and its bookkeeping is requested from PSRAM. From test batch 17 on (during 1.6's tests) the same firmware booted with about 17 KB more free internal RAM, so the step to ~140 KB is a test-setup change, not the 10 s cap; compare versions within a batch. In the same batch, 2.0's speaker labels lower the low point by 6-11 KB (about 144 → 134 KB), set while ESP-DL builds the speaker model at session start.

Word errors, scored clip by clip (standard playlist, lower is better)

Clips whose console text line was lost in any of that version's sessions are left out (a test-harness fault, not the firmware), so each version is scored on 21-26 of the 27 clips. Every version lands between 18.2% and 20.1%; sessions of the same build vary by about ±2 points. The speed changes are bit-identical on fixed test audio, so their text cannot change; the changes that alter what the model hears (1.2's early final and short-reply rule, 1.7's cut at 10 s) show no clear accuracy cost here. The one change that did cost accuracy, the 100 ms tail, was rejected.

5. The language model (1.8)

Everyday speech: word errors by LM size (P4 recordings re-decoded on the Mac)

Tech speech: 180 synthesized sentences (word errors; right column: unknown words recognised)

The P4 logged each caption's raw speech-model output, and the Mac re-ran the device's exact decoder on it (it reproduces every device caption), so every LM was compared on identical audio. The LM is worth about 3 points; its size barely matters, because the speech model gets most words right on its own and the LM mainly breaks ties that depend on common word pairs, which every size keeps. Decode time is set by the speech, not by memory or the session's load, and is the same for every size. The tech term list doubles the unknown words recognised (8 → 16 of 126), but most tech words still fail: the speech model has never heard them and spells them by sound. The next training run adds synthesized tech speech to fix that at the source.

6. Speaker labels (1.9, 2.0)

Each finished phrase gets a session label, and saved transcript lines read "[Person N] text". The model (clova Fast ResNet-34, 1.4 M weights, 8-bit weights with 16-bit activations) turns a phrase into a voiceprint; phrases join the closest voice heard so far, or start a new one. A different speaker model can be dropped onto the card without new firmware.

Phrases labelled with the right person

Labelling time per phrase

Device accuracy is from the four known-speaker conversations (2, 4, 3 and 3 people); repeat runs in the background build landed at 76-85% per conversation, within the run-to-run spread, and the device's voiceprints match the Mac's (cosine 0.997). Two similar audiobook readers merged into one person: their voiceprints are too close for any threshold, a limit of this small model. Turns under 2 s never start a new person. In 2.0, captions did not wait at all: matched clip by clip against the same build without labels, speech end to caption changed by -2 ms (95% range -11 to +4 ms). Labels reach the transcript 0.8-1.9 s after the caption (median); every saved line got its label, in order. Costs: 3.4 MB of PSRAM, about 110 KB of flash, about 0.5 s at session start, and 6-11 KB of internal RAM at the low point. The 3x3 layers of the speaker model got their own cache-sized blocking in ESP-DL (195 → 39 ms each, bit-identical).

7. Trade-offs still open

Accuracy: the 1.3 report flagged about 2.5 points more word errors for 1.2 (18.2% → 20.5% in raw session averages). Scored clip by clip with lost console lines left out, 1.1 to 1.8 all land between 18.2% and 20.1%, so that loss does not reproduce. Tech words are the clear weak spot (about 50% errors on tech sentences); the next training run targets them.

Memory: correction to the 1.3 report: 1.1's internal RAM fell to about 44 KB during each phrase's model rebuild, not 117 KB; from 1.2 the low point is about 112-117 KB (about 143 KB in later test batches). The speaker model's load at session start lowers it by 6-11 KB; moving ESP-DL's short-lived build buffers to PSRAM explicitly would win that back. A 256 KB cache was measured 11-22% faster but costs 131 KB of internal RAM, so it was rejected for excessive RAM consumption; the cache stays at 128 KB.

Speaker labels: similar voices can merge (a whole-conversation relabelling pass or a larger model would help, if memory allows); overlapping speech gets one label.

Not used yet: the faster memory clock (-68 ms) needs a long stability test first. Not yet timed on the glasses themselves. 1.4-2.0 ran in test builds; the stt-speedups branch carries all of it but has not run on the P4 as a whole yet (planned for 0.99.98, after the 15x5 switch).

# Smaller overlap separators · 4 November 2026

The current separator already has int8 convolutions; normalization cores remain FP32 after an observed nonfinite-output failure. Its A8192 export is 554,464 bytes for 91,961 learned parameters. That file size is not the incremental application RAM cost. The static graph screen finds 6,523,904 simultaneously live named activation bytes, dominated by a 6,140,032-byte int8 decoder tensor shaped `[2,47969,64]` plus a 383,872-byte encoded tensor. Actual integrated P4 peak remains unmeasured against the mandatory 30,000,000-byte total-app limit.

## Incremental versus existing STT memory

These separator intermediates are additional work relative to the current STT path. Existing capture buffers may supply the separator input without a second raw-audio copy, but that does not supply the decoder's intermediate tensor. The installed `dl_module_insert_zeros.hpp` marks this operation `MODULE_NON_INPLACE`, obtains distinct input/output tensors and clears and fills the expanded output. It is not automatically reusing the microphone ring buffer.

If separator, recognizer and speaker work run sequentially, an explicit memory plan could share an activation arena across their nonoverlapping lifetimes. Existing model parameters, ongoing capture, retained separated audio and other app state can remain resident. Accordingly, the extra total peak is neither proven zero nor correctly calculated by simply adding every subsystem's peak. Loading, scheduling, allocator behavior and actual concurrency must be measured together. No such sharing has been implemented or qualified for this separator.

A read-only source audit makes that limitation concrete. The installed ESP-DL `dl_memory_manager.hpp` states that each model has its own memory manager and lists cross-model sharing as unfinished work. The current `quartznet_runtime.h` defaults `HW1_STT_RESIDENT_MODEL` to 1; its cached recognizer retains its activation arena between phrases. `ModelCache::dropResident()` destroys that resident model while preserving raw cached weights, so an explicit release-and-rebuild schedule is one possible reuse strategy, with rebuilding/time/fragmentation costs still to measure. Simply running a separator call before a recognizer call does not release the retained recognizer arena. Low-level `ModelContext::root_free()` exists, but freeing it alone leaves tensor pointers/execution state needing a coherent rebuild; it is not a safe application-level sharing shortcut. No runtime source or configuration was changed, and no board was accessed. Exact inspected source hashes are recorded in `runtime-memory-source-audit.json`; these observations do not identify the configuration currently flashed on the device.

The first implementation alternative is a decoder that does not materialize inserted zeros, or serial decoding of the two output channels with shared scratch. These could preserve learned capacity, unlike narrowing, but require exact numerical checks including rounding, saturation, tails and channel layout. A shorter separator window also reduces tensors, but changes the context available to global normalization and separation and must be accuracy-tested. It is not a free memory fix.

## Published alternatives and quantization

The [Conv-TasNet scaling study](https://arxiv.org/html/2303.03005v1) found that shrinking hidden channels while preserving temporal coverage was often preferable to removing dilated blocks. Its models and training are much larger than ours, so its results do not establish an 80% threshold here. The study also warns that reducing encoded feature dimensions can damage reconstruction. That makes the half-filterbank option a controlled accuracy experiment, not an assumed safe substitute.

[FQSS](https://github.com/ssi-research/FQSS) reports 14.75 dB versus 14.78 dB floating-point SI-SDR for its int8 ConvTasNet experiment, using quantization-aware training and distillation. This supports investigating separation-specific QAT, but those are source-separation scores on another model/dataset, not word recovery, speaker-label accuracy, P4 compatibility or our RAM use. We cannot transfer that accuracy claim to this 92k-parameter student.

[TF-MLPNet](https://arxiv.org/html/2508.03047v1) is a relevant different architecture: streaming two-speaker separation on GAP9, with a reported 483 kB mixed-precision model achieving 13.52 dB SI-SDRi versus 14.12 dB floating point. It is not much smaller as a stored model, but its short-chunk design makes it relevant to working memory. The paper's fully int8 variant falls to 10.21 dB, illustrating why quantizing every operation more aggressively can harm separation. Its P4 kernels, state memory, timing, stable speaker identities and downstream word recovery remain untested. The smaller 215k-parameter frequency-compressed variant is another research candidate; the paper does not establish a 215 kB mixed-precision P4 artifact.

[Espressif's quantization documentation](https://docs.espressif.com/projects/esp-dl/en/latest/tutorials/how_to_quantize_model.html) describes W8A8, W16A16 and W8A16. The installed exporter exposes those ESP-DL platforms, with no ESP-DL int4 target. Int4 therefore requires a separately verified runtime/kernel path; it is not an available switch that halves these already-int8 intermediate tensors. Weight-only int4 would primarily save weights, not the multi-megabyte activation hotspot.

## Meaning of “80% of the way there”

Treat this as a benefit-retention target, not 80% of an SI-SDR number or a smaller file. A future size A/B should retain at least 80% of the reduction in speaker-attributed word errors achieved by a specified reference system over the same baseline, on a fresh locked qualification set, while also preserving ordinary/quiet speech and no-speech behavior. Report missed words and label stability separately. The reference must first show a useful improvement; the early current checkpoint has not done so. This interpretation is provisional and does not retroactively change the current frozen selection rule.

Finish the active matched comparison's qualification unchanged; both training arms and development checkpoint comparisons have completed. Prioritize removing decoder expansion without reducing model capacity, and compare the 32-filter/26k-parameter variants under matched data/budgets if the accuracy evidence justifies a new size experiment. A different streaming architecture is a larger porting/training task. None is presently demonstrated to deliver 80% of the required two-speaker caption benefit within the 30 MB integrated peak.
